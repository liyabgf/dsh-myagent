## 2. 不可绕过的执行纪律（新增/强化）

### R1 · 先写后做，无例外

任何命令在执行前必须在物理文档中写明：意图、目标文件、预期结果。身份核验（pwd/git status/git log）是唯一允许的前置只读操作，核验后立即追加到账本，再开始修改。"来不及写"不是理由；写账本是执行的一部分，不是额外的负担。

### R2 · 文件所有权锁定

每个批次在登记时列出允许修改文件和禁止修改文件。禁止文件不得以任何理由触碰，即使"只改一行"。如需跨批次修改，必须先在账本中申请变更合同并等待确认，不得自行扩大范围。

### R3 · 构建只在隔离快照

`pnpm build` 和 `./scripts/gate.sh` 只在 `/tmp` 下的隔离快照中运行。快照包含受控文件和 node_modules 符号链接。本体磁盘产物不被任何批次覆写。快照路径、产物 hash、源码树 hash 记录在账本中。

### R4 · 产物不追踪

`lib/` 在 `.gitignore` 的 `/lib/` 规则下，不进版本库。任何提交不得包含 `lib/` 文件。如发现 `git ls-files lib/` 有结果，立即 `git rm --cached` 并单独提交，不在业务批次中混入。

### R5 · 声称完成需要完整证据

"完成"的定义：最小复现 + 正向测试 + 负向测试 + 变异（改坏→预期红→还原→hash 核对）+ 隔离 gate + 回滚演练。缺任何一项标"部分完成"或"待验收"，不得标"完成"。测试全绿只证明被测命题，不证明合同满足。

### R6 · 退出码精确捕获

任何测试/构建命令的退出码必须从该命令本身获取，不得从管道末端过滤器获取。格式：`cmd > /tmp/out.log 2>&1; echo "exit=$?"`。管道中如有 `grep`/`tail`，使用 `PIPESTATUS` 或先落盘再过滤。不得把过滤器的退出码当测试退出码。

### R7 · 账本可读

所有操作账本必须以 UTF-8 编码写入。不得使用 `cat >>` 追加包含非 ASCII 字节的 shell 变量输出。如需记录 hash，用 `awk '{print $1}'` 而非 `$(shasum)` 内联展开。每次写入后用 `read` 工具确认可读。

### R8 · 变异在隔离副本

变异检验在 `/tmp` 下的隔离工作副本中进行，不在本体变异。步骤：`cp 文件 /tmp/备份` → 在副本改坏 → 在副本跑测试 → 记录真实退出码和输出 → `cp /tmp/备份 文件` → `shasum -a 256` 核对还原。本体源码树在变异期间不可被覆写。

### R9 · 回滚有证据

每个批次必须演练回滚：记录回滚命令、回滚后源码树 hash、回滚后测试结果。回滚失败也要记录，不跳过。未演练回滚的批次标"待验收"，不标"完成"。

### R10 · 不夸大

测试通过 ≠ 合同满足。代码存在 ≠ 行为正确。历史记录 ≠ 当前事实。外层事务保护 ≠ 内层已验证。这些区别在每次结论中显式区分，不用笼统的"通过"替代。
