# 面板易用性改造 · 工程清单（U1–U16）

依据：`docs/v2/22-panel-usability-plan.md`（§1 信息架构 / §2 逐页设计 / §3 代码→控件 / §5 打通矩阵 / §6 使用习惯）。

## 0. 全局硬约束（每个包都适用，违反即返工）

1. **串行**：所有包都改 `panel/index.html` 这一个文件，**必须一包做完、验证完、再开下一包**；不得并行编辑。
2. **不删测试、不弱化断言、不改预期制造绿**。B 阶段的文案更新必须附**「旧断言 → 新断言 + 同一个事实」对照表**，逐条可审查。
3. **每包结束**：完整四步闸门 `./scripts/gate.sh` 读退出码；`node scripts/verify-browser.mjs` 全过；**至少 2 处变异检验，每处做 0.8 强形式**（删断言看会不会绿）；变异还原后**按改动后应有的哈希核对**（§4.86 发现 E：备份要在改动完成之后做）。
4. **每包至少 1 条新真浏览器断言**，并且先在改动前跑一次证明它会红（0.8：先证明装置是活的）。
5. **每包记入 `docs/v2/00-audit-and-plan.md`**，含失败的尝试与错的前提。
6. **不做**：不重写成 SPA、不引框架、不加构建步骤；**不彻底隐藏 JSON**（高级折叠区永远保留，双向同步）。

## 3. 开工前需要你拍板的两件事（只挡 B/C，不挡 A）

1. **「工作」是否并入任务页左侧分组**（方案主张并入；若你想保留独立页，U7/U14 缩小范围）。
2. **新菜单名**：Ticket→**任务**、门禁记录→**记录**、派活保留、排期并入派活、来源解散、设置保留。命名定了 U7 才能动。
