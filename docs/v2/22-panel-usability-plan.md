# 面板易用性改造方案（V3）：从"系统视角"改成"操作者视角"

**一句话诊断**：现在这个面板回答的是"系统里有哪些东西"（Ticket/工作/来源/排期/设置……八个名词，全是系统自己的词），
而操作者每次打开面板问的是**五个问题**：

1. 系统现在正常吗？
2. 有什么需要我？（等我回答的任务、等映射的聊天消息、丢失的请求）
3. 那件活干到哪了、产出了什么？
4. 我要派一件新活（现在派，还是定时派）。
5. 出问题了，怎么修？

**改造原则：每个界面元素必须回答其中一个问题；回答不了的，挪走或删掉。**

---

## 0. 现状诊断（事实，不是印象）

### 0.1 菜单名是系统的词，不是操作者的词

| 现名 | 问题 |
| --- | --- |
| Ticket | 术语。操作者在别处永远见不到这个词 |
| 工作 | 与日常语"工作"撞车，实际是"同类活的流水" |
| 派活 | ✓ 好词，保留 |
| 门禁记录 | "门禁"是系统内部的比喻，操作者的问题是"哪些请求被受理/拒绝了" |
| 来源 | 一页混了 5 个不相关分区：来源、健康、队列、丢失的请求、聊天 |
| 排期 | 本质是"定时派活"，和「派活」是同一件事的两种方式，被拆成两页 |
| 设置 | 只有一个 JSON 文本框（340px 高）+ 3 个快捷字段 |
| 提示词 | 两个大段原文 textarea，管理员级配置却占一级菜单 |

### 0.2 仍以"代码形态"出现的操作面（应改成控件）

| 位置 | 现状 | 应该是 |
| --- | --- | --- |
| `#settings` | 整份设置 JSON（340px textarea） | 分区表单（见 §2.4） |
| `#new-result` | 创建任务后返回的**原始 JSON** | 结果卡片：成功→「打开任务」按钮；被拒→原因+下一步 |
| `#p-worker` / `#p-orchestrator` | 提示词原文 textarea | 分角色卡片：职责说明、字符数、与内置版的差异、单角色恢复 |
| `#sched-error` / `#settings-error` / `#prompt-error` | 裸 `<pre>` 错误文本 | 按字段定位的校验面板 |
| 聊天 `channels` / `identities` | **只能改整份 JSON**（交付物 8 记过的债） | 表格控件：增行/删行/启停 |
| 各处 id | 32 位十六进制全串、`policyVersion`、`triggerId` 直接平铺 | 8 位短 id + 复制按钮，全 id 放 tooltip，「技术细节」折叠区 |

### 0.3 关键任务的点击距离（改造前实测）

| 操作者的问题 | 现在要走 |
| --- | --- |
| 系统正常吗？哪里不正常？ | 点「来源」→ 滚到第二个分区「健康」（2 步 + 滚动） |
| 丢失的请求在哪？ | 点「来源」→ 滚到第四个分区（2 步 + 长滚动，被 5 个分区埋着） |
| 有任务等我回答？ | 顶部下拉换「等人回答」筛选（1 步），但**没有和聊天等待、丢失合并成"需要我"** |
| 接下来会自动跑什么？ | 点「排期」看每条的"下次"（1 步），但总览没有 |
| 修聊天身份映射 | 点「来源」→ 滚到第五个分区「聊天」→ 仍要改 JSON（3 步 + 改代码） |

## 1. 信息架构：8 标签 → 5 标签 + 1 全局抽屉

```
┌─ 顶栏：myagent ─ 状态●(点开=健康抽屉) ─ 槽位 ─ 等我N(红) ─ [暂停] [派活]
├─ 总览        ← 新的落地页（答问题 1、2、5）
├─ 任务        ← Ticket 列表+详情；左侧栏把「工作」变成分组（答问题 3）
├─ 派活        ← 手动派 + 定时派（排期并入，同一个表单一个开关）（答问题 4）
├─ 记录        ← 判定记录 + 丢失的请求（都是"门/队列做了什么"）（答问题 5 的取证）
└─ 设置        ← 来源配置、聊天映射表、提示词、高级 JSON（折叠保底）
```

**「来源」页解散**，五个分区各归其位：来源状态→总览；健康→全局抽屉；队列→抽屉第二栏；丢失的请求→记录页；聊天配置→设置页。

### 菜单改名对照

| 现名 | 新名 | 理由 |
| --- | --- | --- |
| Ticket | **任务** | 操作者的词；"进行中/等人/已结束"筛选chips化 |
| 工作 | **任务页左侧分组** | 不再独占一页；管理表单挪到设置页「工作与项目」 |
| 派活 | **派活**（含定时） | 保留；排期编辑器并入为「定时」开关 |
| 门禁记录 | **记录 · 判定** | "哪些请求进了、哪些被拒" |
| 排期 | 并入派活 | 同一道门禁，同一种表单 |
| 来源 | 解散 | 见上 |
| 设置 | **设置**（分区化） | |
| 提示词 | 设置页内「提示词」分区 | 管理员级，不该占一级 |

**不做的事**：不重写成 SPA、不引框架（仍是单文件、无构建步骤）；**不彻底隐藏 JSON**——设置页保留「高级 · 直接编辑 JSON」折叠区，与表单双向同步（与已实现的 `#settings-quick` 同一机制扩大）。你定过一条规矩：**永远不要只截断而不给出看剩下的办法**，这条同样适用于"不给了 JSON 但没给表单"的反向。

## 2. 逐页设计

### 2.1 总览（新的落地页，全部用现有路由拼装，不动后端）

- **顶上一排状态卡**：进行中 N · 等你回答 N（红，点了直达）· 已结束今日 N · 槽位 x/y · 队列深度。
- **「需要你处理」**（这是本页的核心，合并三处孤岛）：
  等回答的任务（每条带**行内回答框**，省去进详情）+ 聊天等待（列出身份，一键跳设置映射）+ 丢失的请求（列出，跳记录页）。
  **三样东西现在散在三个页面，而这正是"无人值守系统"最该一眼看到的东西。**
- **接下来自动跑的活**：读排期，列最近 3 条下次触发时间。
- **最近活动**：最新 5 条事件/判定（现在只有进了「门禁记录」才能看）。
- 空 5 分钟时显示"系统安静，无事需要你"，而不是一排 0。

### 2.2 任务页

- 左栏：工作分组（可折叠）+ 全部；筛选从下拉改成 chips（进行中/等你/已结束）。
- 列表行：标题、阶段胶囊、相对时间（"3 分钟前"而非绝对时间戳）、工作名标签。
- 详情页（改最多）：
  - **id 全部缩短**：8 位 + 复制按钮；`policyVersion`/`triggerId`/`scope` 原文挪进「技术细节」折叠；
  - **"此刻"提到最上**（这是看进展的人第一眼要的，现在在范围/附件之后）；
  - 报告/输入/产物三个长列表已有界滚动保留；
  - 行动按钮（回答/备注/重试/停止）**吸底固定**，长详情页滚到底不用爬回来。

### 2.3 派活页（含定时）

- 一个表单，顶部一个开关：**「一次性派 / 定时派」**。定时模式出现时刻/星期/cron 选择（复用现有排期编辑器逻辑）。
- 提交后的 `#new-result` 原始 JSON 改成结果卡片（见 §0.2）。

### 2.4 设置页（JSON → 分区表单，分区可独立保存）

| 分区 | 控件 |
| --- | --- |
| 受理 | 模式单选、全局暂停开关 |
| 执行 | 并发数 stepper、模型下拉/输入、prepare 命令输入 |
| 收件目录 | 目录路径、轮询间隔 |
| 聊天 | 启用开关、轮询间隔、**身份映射表（增/删/改，关闭"只能改 JSON"的债）**、**频道表（增/删/启停）** |
| 各来源 | 每来源的允许发起者 chip 编辑、拒绝/暂停开关 |
| 提示词 | 分角色卡片：说明、字符数、与内置差异、单角色恢复 |
| 高级 | 折叠的整份 JSON（保底逃生口，双向同步） |

### 2.5 健康抽屉（全局，任何页一键）

顶栏「状态」胶囊可点 → 右侧抽屉：健康各条目（含详情原文）+ 队列。**从任何页面 1 步可达，替代现在"来源页第 2 分区"。**

## 3. 落地顺序（每阶段闸门 + 真浏览器 + 变异，独立可回滚）

| 阶段 | 内容 | 对既有测试 |
| --- | --- | --- |
| **A（纯增量）** | 总览页、健康抽屉、id 缩短、结果卡片、提示词卡片 | **0 条改动**（全是新增 DOM；173 处 `button()` 文案不动） |
| **B（文案）** | 菜单改名（Ticket→任务、门禁记录→记录…）、筛选chips | **约 30–40 处**测试里的按钮/文案断言需随产品文案更新。**这是合法更新而不是弱化**：断言的事实不变（按钮仍做同一件事），变的只是它叫什么。**每处改动我都列出"旧文案→新文案+同一断言"的对照**，可逐条审查。 |
| **C（结构）** | 排期并入派活、来源页解散、设置分区表单 | 改动最大（含 18 处 `button('来源')` 的归属迁移），**最后做**，且做完跑真浏览器全链路。 |

**验收标准（每阶段）**：
1. `./scripts/gate.sh` 退出码 0；
2. `node scripts/verify-browser.mjs` 全过（新页/新抽屉各加断言：显隐互斥、点击距离实测）；
3. 新断言至少 2 处变异检验 + 0.8 强形式；
4. **点击距离表重测**：§0.3 的五条路径，每条 ≤ 目标步数（如"哪里不正常"从 2 步+滚动 → 任意页 1 步）；
5. 每阶段截一组图给你过目——**"方便不方便"最终是你的判断**，自动化只能保证没坏。

## 4. 风险与如实声明

- **B/C 阶段的测试更新量不小**（173 处 `button()` 调用中约 30–40 处、18 处 `button('来源')`）。我不会为了少改测试而砍方案；也不会在同一批次里既改产品又改断言——**每个批次只做一件事**，断言对照表随批附上。
- **「需要你处理」的总览行内回答框**要防止 3 秒轮询吃掉输入——复用详情页已验证的草稿保持机制（`draft` + 焦点保护），并在总览页关闭 Ticket 轮询（列表轮询不动输入框）。
- **聊天身份映射表**关的是交付物 8 记过的债，但**改的仍是同一份设置文档**——保存路径不变，只换编辑面。
- 本方案**不动 `src/`**（除阶段 A 若需要聚合路由；先全部客户端拼装，聚合路由只在确有性能问题时加）。

## 6. 人类使用习惯作为设计依据（新增）

操作者的习惯不是空白，是在邮件、IM、任务工具里养出来的。**界面符合惯例的部分零学习成本；违反惯例的部分，
每一处都要用户重新学一遍。** 逐条映射到本面板（依据：Nielsen 可用性启发式 + 邮件/IM/看板的通用惯例）：

### 6.1 习惯 → 本面板的规则

| 人类习惯 | 面板规则 | 状态 |
| --- | --- | --- |
| **红点数字＝"有事需要我"**（IM/邮件徽标） | 菜单项带徽标：任务(3 等你)·记录(1 丢失)；顶部胶囊同色同义 | 新增，A |
| **收件箱心智：要处理的排最前，处理完就消失** | 总览「需要你处理」区：回答完任务即离开列表 | 新增，A |
| **先搜索，再浏览**（Ctrl+F / 顶部搜索框） | 顶部全局搜索：任务标题/id、工作名、排期名 | **新缺口，B** |
| **相对时间**（"3 分钟前"，悬停看绝对时间） | 列表与详情时间一律相对化，title 带完整时间 | B |
| **表单：标签在上、主按钮在最后、危险变红且两步确认** | 已遵守（页内确认、无原生弹窗）——保持 | ✓ 已有 |
| **空状态是教学时刻**（不是"无"） | 每个空列表给"下一步"按钮：如"还没有排期→建一个" | 部分已有，B 补齐 |
| **操作结果 1 秒内可见** | toast 已有；列表行内变化要就地出现，不整页闪 | ✓ 已有（搬移机制） |
| **草稿永不被后台刷新吃掉** | 已有（draft + 焦点保护）——总览行内回答框复用同机制 | ✓ 已有 |
| **Esc 关闭 / Enter 提交** | 抽屉与文件查看器 Esc 关；行内回答 Enter 发送 | B |
| **数字右对齐、状态用色不用文字** | 计数列右对齐；阶段胶囊色即语义 | B |
| **同一操作在每页同一位置** | 「打开」一律行尾；危险按钮一律最右 | B（一致性巡检） |
| **渐进披露：默认简单，高级折叠** | JSON 折叠保底；`policyVersion` 等进「技术细节」 | 已在 §2 |
| **Hick 定律：选项越少选得越快** | 一级菜单 8→5 正是此意；筛选 chips ≤4 个 | 已在 §1 |
| **Jakob 定律：用户期望你的站和别的站一样** | 顶栏+左侧导航+抽屉+徽标，全是最常见 SaaS 骨架——**不为新颖而新颖** | 本方案整体 |
| **设置表单：分区独立保存 + 脏状态提示"未保存"** | 设置页每分区一个保存按钮；离开未保存分区时提示 | B |
| **触屏可达：不依赖 hover** | 健康 tooltip→抽屉（§5 缺口 5）正属此类 | A |

### 6.2 这条依据对既有决策的**修正**

1. **总览＝落地页的理由更硬了**：人的第一问是"有什么新事"，落地页就该是收件箱，不是任务列表。
2. **「等你回答」要用行内回答框**：邮件"回复"从不离开收件箱；现在要进详情→找输入框→滚动，违反的正是这个习惯。
3. **新增全局搜索**（原方案漏了）：任务多了之后，人的第一动作是搜，不是翻左侧分组。B 阶段补。
4. **导航徽标**比顶部胶囊更符合习惯：人看导航先于看顶栏，徽标让"需要我"出现在视线落点。
