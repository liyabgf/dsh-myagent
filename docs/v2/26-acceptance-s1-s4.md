## 第一部分：不需要你的凭据（本机面板就能验）

### S4 任务删除

1. 任务页顶部多了一档「**已删除**」筛选（原来 4 档）。
2. 打开一张**已结束**的任务 → 底部最右「**删除这张任务**」。
   - 点一下出现确认块，里面有一句**量出来的**后果：「目录 X：N 个文件、M」——数字应该和你目录里的一致。
   - 默认选「留着产出的文件」，另有一个勾选「连任务记录也不留」；勾上时确认按钮的字会变成
     「确认删除（记录也不留）」。
   - 确认块里写着两种选择都**不动进气记录**，以及为什么。
3. 用「留着文件 + 留墓碑」删一张 → 它从所有列表消失，但「已删除」一档里能查到：
   标题、授权人、删了多少（N 个文件、M）、什么时候删的。**去磁盘看目录还在**。
4. 打开一张**进行中**的任务点删除 → 当场弹「运行中的任务不能删：先停止它」，**确认块不会出现**。
5. 勾上「连任务记录也不留」删一张（拿一张不重要的）→ 列表与「已删除」里都没有它了；
   但在「记录」页里还能查到它当初的判定——这是刻意的，删任务不等于删"它曾被要求过"。

### 面板上认得出分诊任务

这一条在分诊**开着**之后才有数据可看（见第二部分第 3 步）：列表里它带一个「分诊」chip，
点开有一段说明，告诉你"一轮就结束是正常的"以及开关在哪。

### 前台的新工具

在主 Session（myagent-main）里直接问它"你有哪些工具"，应当列出：
`myagent_reply`（把话送回请求者）与 `myagent_close_ticket`（给分诊任务收尾）。
B2（默认）下用不到 `close_ticket`，B1 下它是必需的。

## 第二部分：需要你的电报 bot（我没有验证过这部分）

身份映射我已核实是好的（你的 id <telegram-user-id> → operator），所以消息能进门禁。

### S1：卡住的任务会说话了

之前的静默：worker 没写报告、任务停在 `waiting`，面板说「等我回答」，电报那边**一个字没有**。

验法：发一条会产生任务的消息（例如「读 X 然后写摘要」），等它跑起来后**在面板上停止它**——
你的电报应当收到一条「…stopped, needs a push」，说它停了、需要有人推一把，而不是继续沉默。
（`blocked` 同理：worker 报告问题时，前台会被告知、由它决定处理。）

### S2：watchdog 放弃也会说话，而且只说一次

设置里把 `maxActions` 保持默认 2、`launchStuckMs` 调小（例如 60000），丢一条起不来的请求
（比如给一个不存在的目录）→ watchdog 放弃时：请求者收到一次「needs a person」，
前台被唤醒（带 `myagent_retry_ticket`/`myagent_stop_ticket` 与目录）。
**此后每一轮它都会重新升级（历史里能看到多条 escalated），但请求者只会被通知第一次**——
重复警报只会训练你忽略它。

### S3b：打开分诊（你决定何时）

「设置 → 进气」把分诊打开（`desk` 默认 `dedicated`），然后在电报里发一句一眼能答的：
「**现在有几张在跑？**」

应当发生：这张请求先过门禁（你的身份映射），然后由**专职分诊台**处理——它大概率**直接回答**
（一句「三张在跑…」回到你的电报），面板任务列表里出现一张带「分诊」chip 的任务，一轮就结束。
若你发的是真活（「读 X 写摘要」），它应当开一张任务，且**那张任务的报告会回到你的电报**
（这是 `report_to_ticket` 的回程地址）。

### B1：分诊台换成你自己的 Session

设置里 `desk` 改成 `main`，再发一句「现在有几张在跑？」——
这次**不会有任何新 Session**：请求排进你正在用的主 Session，由它（带着你已经攒下的上下文）决定，
然后用 `myagent_close_ticket` 收尾。你在主 Session 里看得到那条带 `TRIAGE_BRIEF` 指令的请求。

不想要就切回 `dedicated`——它是默认值，理由写在设置的注释里：进气是无人值守的、你的对话是有人的。

## 我没做、也如实说明的东西

- **S2 的"里程碑/定时摘要"进度**：没做。前台与面板永远收得到 progress；请求者只做了"被问"的前置
  （前台攒着进度，能答上来）。加没有消费者的 `milestone` 标志是投机机械。
- **`watchdog.silentMs` 仍默认 0**：S2 的结论是不新造 staleness 检测、把升级路径接通。要不要打开是你的决定。
- **变异守卫的一处欠账**：面板「分诊」chip 的第二层守卫（条件式浏览器断言）没写——分诊默认关，
  真浏览器层现在看不见它。已记入 §4.126。
