## 1. 加了什么，各用哪些路由

| 位置 | 内容 | 用的路由 |
| --- | --- | --- |
| 新标签「工作」`#tab-works` | 左：项目列表 + 工作列表 + 两个新建表单；右：项目或工作详情。空状态写成"下一步做什么"，不是"无" | `GET projects`、`POST projects`、`GET projects/:id`、`GET works[?project=]`、`POST works`、`GET works/:id` |
| 工作详情 | `scope`、`note`、项目名、创建时间，Ticket 列表**按 `workSeq` 排序**；点一行回到 Ticket 页打开它 | `GET works/:id` |
| 项目详情 | `note`、它的工作列表；点项目行第二次退回"全部" | `GET projects/:id` |
| Ticket 列表行 | 所属工作的**名字**（不是 id）+ `第 N 位` | `GET works`（与列表并行读；读不到就退回不显示标签，不报错） |
| 详情「归属」行 | 工作名 + 短 id + `第 N 位`；无归属时写"未归入" | `GET tickets/:id`（`workId`/`workSeq`）、`GET works` |
| 详情「归入工作」 | 工作下拉 + 按钮；**已结束的 Ticket 也给**（归档是记账，不是新授权） | `POST tickets/:id/work` |
| 详情「产物」 | 每条 `path` / `at` / `note`；点路径打开、点「下载」下载，走的是产出文件用的同一条文件路由与同一个 Blob 下载路径 | `GET tickets/:id`（`artifacts`）、`GET tickets/:id/file?path=` |
| 详情「依赖」 | 两个方向**分开且各自标注**：「它等这些（它们没完成，这张就不会启动）」/「这些在等它」。每条可「打开」对端、可「删除」（二次确认，不弹原生对话框）。加边可选 `on: done\|ended`，也可手填 id；`dependency_cycle` 的**服务端原文**直接进 toast | `GET tickets/:id/dependencies`、`POST tickets/:id/dependencies`、`POST tickets/:id/dependencies/drop`、`GET tickets?state=all&limit=200`（对端标题与候选） |
| 详情「历史」 | 最新在前；每行 `#seq`、本地时间、`type`、`by`（`人/代理/系统 · id`，所以 `watchdog` 与某条规则的 id 分得开）、`detail` 逐键展开成 `键: 值`。底部「共 N 条 · 已显示 M 条 · 最新在前」+「再读 20 条」 | `GET tickets/:id/events?limit=N` |

顺手修的两个既有缺陷，都是操作者旧投诉的回潮：

- **输入被硬截断**：报告超过 6 条有"展开全部"按钮，输入超过 6 条**没有**——第 7 句回答就这么消失了。
  现在两者共用一个按钮（`展开全部 N 条` / `只看最近 6 条`）。
- `tests/panel.spec.ts` 文件头声称"有 4 条 `it.fails`"，实际一条都没有；注释在替文件说谎，已改成事实。

其余旧投诉逐条核过，均**未回退**：详情每 3 秒自动重读；产出可打开可下载；有实时进展；输入框在按钮之前；
停止原因是页内输入而非 `prompt()`；来源/健康/队列是表格而非 `<pre>`。

## 2. 刷新与"不丢操作者的位置"

- 轮询重画时，`此刻 / 产出 / 文件视图 / 依赖 / 历史` 这几个异步面板是**搬移**而不是重建（`data-for` 记住属于哪张
  Ticket），所以新数据到达之前不会闪成"读取中…"。
- 历史只在 `count`、`returned`、最新 `seq` 有变化时才重画：日志只增，没变化还重画等于每 3 秒把操作者在长日志里的
  位置抹掉一次。
- 跨刷新保留：未提交的草稿（回答、备注、停止原因、加边的三个字段、归入工作的选择）、报告/输入的展开状态、
  打开的文件、删除边的二次确认、已放宽的历史条数、页面滚动位置与历史自己的滚动条位置。
- `#ticket=<id>` 深链照旧工作。

## 4. 宿主插件旧于页面时的行为（本轮真实踩到）

页面每次请求都从磁盘读，插件不是。存了文件、没重载 bundle，就会得到"新页面 + 旧 API"。
本轮线上就是这样：`127.0.0.1:3080` 对 `GET /api/projects` 回 `{"error":"No route for GET /myagent/api/projects"}`，
而页面每 5 秒问一次、每问一次弹一次 toast。

处理：**探测一次**再决定（`GET projects`）。时机是启动、`刷新` 按钮、设置保存后、横幅上的「重试」——
**定时器不探**，否则"停止轮询"就是空话。

- 200 → 后端有 V2 路由，一切照常，无横幅。
- 错误文本含 `No route for` → 后端旧于页面：顶部一条横幅说明原因与做法；新各节**不再发请求**，就地渲染一行
  指向横幅的说明；`load()` 与该页的 catch 不再为这类错误弹 toast。
- 其它错误（同源栅栏、库锁住、500）→ **不下结论**，保持原行为。把版本问题猜成"旧"，会在真有这些路由的宿主上
  把功能藏起来，那是同一种安静的坏。

**选择说明**：解释只放在**顶部一条横幅**里，各节只留一行指向它。五个面板各自重复同一段话，会把"唯一能做的事"
埋掉。这些节**不隐藏**——路由缺失应该说出来，改动是从"每 5 秒说一次"变成"说一次，然后闭嘴"。
另外，只会失败的两个控件（归入工作、加一条等待）在该状态下不渲染：一个只能失败的按钮比没有按钮更坏。

线上旧插件宿主实测（jsdom + 真 fetch 代理到 `127.0.0.1:3080`，跑满两轮 5 秒刷新）：横幅出现；
整段会话对 V2 路由**只发了 1 次请求**（就是探测）；**toast 0 条**；`此刻`（worker Session、已载入 · idle、第 1 轮）、
`产出`（`RESULT.md 1.2 KB` + 下载按钮）、kv 各行、报告、结果、头部计数、5 秒刷新全部照常。

## 5. 还缺什么

- **要看到新各节的数据，必须重载插件**（或重启宿主）。截至本文，`127.0.0.1:3080` 上跑的仍是旧 bundle：
  `GET tickets/:id` 的返回里**没有** `artifacts`/`workId`/`workSeq` 键，`projects`/`works`/`events`/`dependencies`
  ~~全部 404~~ **【已过期，见更正】** 这段写于日常宿主还加载着旧 bundle 的时候。2026-11-04 06:2x 只读实测：`projects`/`works`/`tickets/:id/events`/`tickets/:id/dependencies` **四条全部返回 200**，`tickets/:id` **确实带 `artifacts` 键**，`/api/state` 带 `policyVersion`。原因是 `pnpm build` 触发了宿主热重载（**S37**：日常库也因此从 schema 1 迁到了 5）。仍然成立的部分：`tickets/:id/progress` **不带 `usage` 键**，所以已加载的 bundle 早于第 26 轮；而 `workId`/`workSeq` 不在详情视图是**正确的**——它们在 `ticketSummary` 上（`views.ts:54`），所以那半句不能用来判断 bundle 新旧。
  重载是操作者的决定：我没有重启宿主，也没有调用 `plugin_manager`。
- 工作页没有改名与删除：API 只有 `POST`，没有 `PUT`/`DELETE`，面板也就没有。
- 依赖的对端候选来自 `GET tickets?state=all&limit=200`；超出这 200 张的旧 Ticket 只能手填 id。
- 深链只有 `#ticket=<id>`，没有 `#work=<id>`；工作页的开合状态跨 5 秒刷新保留，但不进地址栏。
- 历史没有过滤，也没有 `type` 的中文对照：`type` 按原词显示（与 `stage` 一致），不能只看某一类。
- `GET triggers` 仍然没有任何页面用它（与本轮之前一致，契约测试仍把它排除在外）。
- 真浏览器未验证：所有面板断言都跑在 jsdom（无 CSS、无真 HTTP）。本轮额外用 jsdom + 真 fetch 打过一次线上宿主，
  那仍然不是浏览器；`scrollTop` 恢复、横幅的 flex 排版这类只有真浏览器能证。
